## 1. System topology and replica semantics

Ten role families Q01–Q10 each consist of P (primary), T (blind twin/reproduction and failover), X (heterogeneous challenger), and V (independent verifier): 40 persistent logical identities. Identity count is distinct from deployed workers, concurrent inference slots, independent trained checkpoints, and resident model runners. Do not claim forty simultaneous models or forty trained agents. Replicate state and task responsibilities, not unnecessary copies of immutable base weights.

Each identity has independently versioned context, retrieval index, compact ML learner, checkpoint lineage, competence history, error memory, scoped capabilities, experiment quota and work queue. A replica may start from the same approved base checkpoint; subsequent learning, seeds and evaluation receipts remain distinct. Identical seeds/checkpoints/inputs are reproduction, not independent statistical evidence. Same-model agreement is correlated. X should use another algorithm or model family when appropriate, and V should prefer deterministic tests, mathematical checks and protected evaluation data. No replica inherits unearned trust, qualification or permission from its parent. Replacements inherit the role contract and explicitly versioned state, not a hidden conversation.

The federation is one system with shared durable task/evidence state:
ICARUS decision-time inputs and GitHub work -> command plane -> task graph -> resource broker -> specialist cells -> independent verification -> Reality Court -> knowledge and training plane -> next experiment / qualified ICARUS research result.
MYRIAD provides the capability evolution and experiment population layer; POLYMIND selects qualified execution adapters; NEXUS/AION supply causal and bitemporal input/settlement evidence; UMBRA supplies simulation and counterfactual testing. JANUS/PROMETHEUS and DAEDALUS provide lineage, research routing and validation patterns where their existing implementations qualify. No new disconnected duplicate platform. The master record stays in the canonical shared repository branch and coordination bus.

## 2. Supreme coordination: deterministic authority, learned recommendations

A deterministic supervisor (not an unbounded LLM) owns task leases, immutable task IDs, resource reservations, authorization, evaluation promotion and conflict handling. Q09 recommends routes from learned performance; Q01 proposes dependency/contract design; neither can override the supervisor. A council of Q02/Q03/Q05/Q06 and role-specific reviewers recommends scientific priorities. Reality Court independently evaluates evidence and preserves dissent and failed experiments. A single supervisor leader per local task store uses fencing tokens; a stale leader cannot commit newer results. Recovery from interrupted work relies on persisted task and lease state, not chat memory.

Task graph: objective -> capability selection -> dependency expansion -> admission -> execution -> receipt -> blind reproduction/challenge -> independent adjudication -> accepted/rejected/deferred -> learning eligibility -> candidate training -> validation -> checkpoint promotion or rollback. Detect cycles before admission. Use bounded fan-out, attempts, depth, wall-time, token and memory budgets; no unlimited recursive spawning. Parent tasks wait for explicitly required child evidence, not every optional branch. Prioritize work by expected scientific value, uncertainty reduction, cost, dependency criticality and aging; reserve capacity for verifier/recovery tasks. Learn rankings from verified results, never let learned ranking bypass hard constraints. Use backpressure, work stealing only with valid leases, stable idempotency keys, timeout/circuit breaker, retry classification and dead-letter queue. Prevent duplicate tasks from committing twice. A duplicate result is preserved as reproduction evidence only when explicitly requested.

For critical research: primary and twin independently seal results before seeing each other's output; challenger attempts to falsify the claim; verifier checks source hashes, deterministic tests and frozen evaluation protocol. Court returns accept-for-research, reject, needs-evidence or defer. No majority vote can overrule a failed invariant, prohibited data use, unsafe action, missing license or protected holdout breach. A disagreement produces a bounded follow-up experiment, not automatic averaging or endless debate. Record all votes, model/algorithm family, dependence, uncertainty and exact reasons. Same-family repeated answers do not multiply independent sample size. Lower-risk documentation triage can use fewer replicas; coverage of all roles does not require spending four inferences on every trivial task.

## 3. ML integrated into every agent

Every identity must have a real trainable numerical component with a declared objective and independent checkpoint namespace. LLM prompts, memory retrieval, role assignment and model inference by themselves are not ML training. The proposed initial learners and label contracts for all forty identities are in the registry. Use compact CPU-friendly models first. A role can use multiple qualified learners, but do not instantiate heavy libraries or load all checkpoints simultaneously merely to meet an identity count.

Common learning stack per identity:
- Perception: typed, causally available features, source/revision hashes, schema/version, quality and missingness flags; no future-derived context.
- Reasoning: qualified LLM or deterministic algorithm selected per task; optional embeddings for retrieval, never confuse embeddings with forecast labels.
- Skill learner: role-specific supervised classifier/regressor/ranker, anomaly detector, Bayesian estimator, symbolic search or online model as specified. Its inference outputs uncertainty, input fingerprint, checkpoint hash, applicability and abstention.
- Meta learner: cost-aware competence and task-routing model based on independently verified useful outcomes, measured resource use and latency. Start with deterministic baselines; learned challenger cannot modify hard budgets or rights. Separate role learner from system scheduler's own learning state.
- Episodic and semantic memory: immutable receipts plus retrieval index; learned ranking for relevance, conflict and staleness. No raw private records or secret values uploaded to GitHub.
- Evaluation: frozen role-specific exam and held-out tasks, deterministic acceptance tests, independent labels, error analysis, drift monitoring, comparison with trivial baseline, prior champion and challenger.
- Recovery: versioned model manifest, bounded checkpoint storage, immutable parent lineage, rollback pointer, audit receipt and last known good candidate.

Training event protocol: task context is frozen before prediction; store prediction with decision_ns, target/horizon, source availability, agent and learner revision. Settlement is admitted only after label availability and independent verification, with explicit domain (synthetic, historical, paper) and revision. Training pool uses only previously eligible settled examples, excludes protected final tests, records all selection attempts and avoids leakage across related replicas, overlapping windows, instruments and derived examples. Define independent grouping by task family/source/time block; duplicates do not artificially multiply sample counts. Separate development, calibration, rolling evaluation and final protected holdout. Fit preprocessing on training only. Use purged/embargoed validation for temporal labels where applicable. Record failed and inconclusive trials; do not optimize a repeated final exam. A learner with insufficient labels remains untrained/abstaining; do not manufacture labels from the agent's self-assessment.

Training stages: (A) deterministic baseline and feature/label contract, (B) small supervised/offline baseline, (C) role-specific online adaptation in shadow mode, (D) challenger experiments, (E) independently approved checkpoint promotion. A candidate must have training manifest (code, data, split, objective, seed, parent weights, package versions, license and limits), finite outputs, meaningful held-out improvement or justified efficiency gain, acceptable calibration and regression behavior, resource qualification and rollback. Declare thresholds before accessing evaluation; where sample size is insufficient, report uncertainty and defer. Never update the deployed champion in-place during evaluation. Train on a separate candidate state, then atomically switch an approved checkpoint pointer. Agents may propose code/model changes, not execute arbitrary generated commands or rewrite their own authority. Online learning uses delayed verified labels and explicit drift windows. Changes to safety, authority, budgets and scoring criteria require authorized review. Model/adapter fine-tuning is optional after a real training corpus, compatible hardware, license, and qualification exist; no assumption LoRA or full LLM training fits current machine.

Cross-agent knowledge transfer: share typed evidence claims and reusable skills with origin, confidence, source, domain and revision. Distill from independently validated teacher outcomes only; keep student evaluation independent, preserve negative examples and version conflicts. Federated or ensemble learning is a later candidate for compatible features/labels; do not average unrelated checkpoints or assume different architectures can merge. Test knowledge transfer versus no-transfer baseline and avoid train/test contamination. Research-only policy optimization and offline RL require logged behavior policy, support checks and independent evaluation; not autonomous financial trading.

## 5. Shared resource broker

One admission broker spans Ollama, llama.cpp, ONNX, PyTorch, CPU classical ML, simulation and retrieval. It must consider all active owner workloads, baseline system memory, resident models, distinct load costs, per-request context and training activations, worker processes, shared memory, estimated uncertainty, disk writes and CPU concurrency. Retain at least 1,800,000,000 bytes available physical RAM per owner instruction; no guarantee against unrelated OS memory changes. Track minimum observed RAM during jobs, not only pre/post snapshots; stop admitting work on pressure, safely cancel only owned work when possible, and preserve recovery receipt. Use bounded threads/processes, account for native-library thread pools, avoid oversubscription. Admit short CPU-only tasks alongside large inference if measured cost permits, not by a fixed assumption that every identity is cheap. No uncontrolled paging, daemon restarts, external job eviction, or reserve reduction. The last snapshot of available RAM was only 2.48 GB with two resident runners; actual current headroom must be rechecked.

Plan a low-footprint persistent registry and lazy checkpoint loading. Deduplicate immutable artifact bytes by verified digest; logical agent state remains distinct. Never delete original repository histories, models or owner data for capacity. Allocate explicit training compute windows only when permitted; checkpoint/resume long jobs. Optimize accepted evidence per second, not request count or number of agents. Benchmarks compare 1/2/4/10 admitted concurrent requests and mixed-backend workloads when supported; 40 identities may be queued even if only one worker runs. Add hardware or remote capacity only after approval. Current Ollama dispatcher is a bounded distinct-model wave prototype; shared-weight concurrency, cross-runtime leases and per-agent training are not yet implemented.

## 6. Durable data contracts

Proposed local transactional store (SQLite candidate; do not repurpose active ICARUS database) with tables for agents, capabilities, model_artifacts, checkpoints, tasks, task_edges, leases, resource_reservations, runs, claims, receipts, predictions, settlements, datasets, training_runs, evaluations, promotion_events and discovery_dispositions. Version schemas and migrations. Use transactionally enforced uniqueness, monotonic lease fencing, dependency state checks, checkpoint manifests, idempotent settlement IDs, append-only events and trusted head verification. A hash chain alone cannot detect truncation without an external trusted checkpoint. GitHub is durable reviewed code, schema, manifests and sanitized handoff; not a high-frequency distributed lock or raw market data store. A single writer owns each local store; if scaling across devices, establish an explicit coordination transport and consistency contract rather than relying on concurrent Git writes. Never promise distributed exactly-once execution; make committed effects idempotent and replayable.

Minimum task envelope: task_id, parent_id, DAG revision, role/replica, objective, domain, input reference/hash, decision/availability, allowed capabilities, dependencies, expected evidence schema, budget, attempt limit, deadline, resource estimate, lease and fencing version. Minimum result: run_id/task_id, attempt, worker/backend/model digest, prompt/learner revision, input/output hashes, timestamps, metrics, actual resource use, execution status, verification state, artifact references and failure reason. Minimum learning record: frozen feature hash, prediction/target, label availability, independent settlement and domain, split/group identity, candidate checkpoint lineage, train/eval manifests and promotion decision. Agent memory is a derived view of accepted/rejected evidence, with invalidation when a source changes; preserve historical receipts rather than rewriting them. Schema validation and authorization before processing any tool output or retrieved instruction. Treat all model output and external source content as untrusted data; capability allowlists, typed action proposals, no shell execution from generated text, no secret leakage or unauthorized network access.

## 7. UMBRA and ICARUS scientific cycle

Example: ICARUS exports a frozen Pulse fingerprint and a decision-time NEXUS/AION capsule. Q08-P produces a forecast using a qualified numerical challenger; Q08-T reproduces on a blinded copy; Q08-X applies a different model or baseline; Q08-V checks feature timing, split, calibration and label contract. Q02/Q03 generate falsifiable regime or dynamical hypotheses; Q05 proposes algorithms; UMBRA produces paired worlds with common exogenous seeds and a single explicit intervention. Q06 and role verifiers check counterexamples and execution assumptions; Reality Court evaluates against independent statistical gates. Once an actual eligible label settles, the responsible learners may train a candidate and MYRIAD records the evolutionary attempt. ICARUS receives reviewed shadow-only recommendations and failure evidence, not unvalidated orders. Q07 retrieves reusable implementation evidence, Q04 proposes tested changes, Q01 coordinates integration and Q10 writes restart-ready handoffs. All 275 project dispositions and previous capability findings remain in scope.

Synthetic worlds test causal hypotheses, not real market predictive truth. Separate synthetic, historical, paper and live evidence; no cross-domain promotion without explicit independent qualification. Preserve original Pulse; no silent edits, broker arming, execution authority, unapproved deployment or main merge.

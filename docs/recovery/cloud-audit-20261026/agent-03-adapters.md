## Concrete defects

**P2 — Unusual Whales crypto discovery is blocked by ICARUS's secret filter before HTTP.** Engine `tools/provider_exhaustive_collection.py:42` defines `SECRET` to match the substring `token`. `tools/provider_supplemental_transport.py:81–83` rejects any matching path. The admitted catalog endpoint is `/api/crypto/list_tokens` (`config/provider_endpoint_catalog_supplemental.json:23`), so its ordinary resource name matches the filter. Offline reproduction, after `base.install_extensions()`, calling `request('unusual_whales', '/api/crypto/list_tokens', {'limit':1000}, 'offline-placeholder')` raises `ValueError: unsafe path` before opening transport. The current persisted receipt corroborates this exact operation/failure (`automation_intelligence/provider_collection_v1/latest/unusual_whales.json:23–26`). Its separate screener 401 at lines29–31 is an external authentication blocker; repairing that credential alone cannot repair crypto discovery. Fix by validating pinned endpoint paths independently from secret-bearing query/header fields, preserving transport/path safety.

**P2 — CSV feed can assign future portions of a source bar to an earlier target bar.** Icarus `icarus_engine/feeds/bars.py:264–283` rejects only `g < src`; all larger intervals aggregate by source *open* time without requiring divisibility or checking source-end containment. Reproduced a 120-second feed requested at 180 seconds: the source bar `[120,240)` is wholly included in output `[0,180)`, including its high/close from after180; the bar `[240,360)` is relabeled as open180. Returned values cannot represent genuine three-minute bars. `FileFeed.GRANULARITIES` does not enforce admission. Require compatible intervals and source/target alignment, or return an explicit unavailable result. This matters to direct `HistoryHub.candles` consumers and offline research; runtime's later `on_sub_bar` divisibility guard does not repair already misaggregated output.

**P2 — live OHLC admission bypasses the stronger historical/CSV validation.** Databento `_ohlcv_record` (`icarus_engine/feeds/databento.py:294–303`) checks finite prices individually but admits `high < low`, opens/closes outside the range and negative/nonfinite volume. Offline reproduction returned `Bar(o=100,h=90,l=110,c=100,v=-1)` without error. Live `_live_callback` immediately buffers that record at lines637–648; runtime polling forwards completed rows at `runtime.py:1350–1367`, and `on_sub_bar` (`runtime.py:823–842`) checks ordering/calendar but no geometry/volume. Historical batches have `make_bar_batch_receipt` validation (`runtime.py:1061–1072`), while CSV ingestion rejects the same malformed data (`feeds/bars.py:144–157`). Apply one shared validation boundary before live buffering, with explicit unhealthy status on rejection. This is a robustness defect, not evidence that Databento has actually delivered malformed bars.

**P2 — depth research context has a broken ledger path and no verified runtime handoff.** Engine `config/data_ingestion_manifest.json:25` directs consumers to nonexistent `automation_intelligence/depth_research_context_v1/`. The builder actually writes `automation_intelligence/cl_lab/databento_depth_research_context.json` (`tools/databento_depth_research_context.py:20`; workflow `.github/workflows/databento-depth-research-context.yml:85`). The committed artifact is historical: `snapshot_at_utc=2026-10-05T22:49:00+00:00`, `status=READY` (`…json:20716–20721`), with156,928 rows solely secondary/third (`…json:20723–20728`). Current Sentinel records the publication workflow failing (`automation_intelligence/sentinel/data_health.json:429–433`), and the mandated ledger explicitly preserves the primary-account integrity gap. Neither the Engine historical document map (`icarus_engine/interrepo_bridge.py:68–95`) nor Icarus's strict map (`icarus_engine/brain_sync.py:64–79`) admits this depth context; source searches found no runtime reader for its filename. Icarus overview fetches lane manifests only (`overview_command_center.py:25–33`). Correct the evidence path and add a source-qualified, historical-only consumer if required; retain the primary integrity refusal. Existing summary/artifact presence does not demonstrate depth-feature consumption by Brain/strategy.

## Actual wiring and boundaries

Databento normalizes fixed-point prices, preserves nanosecond event/receive clocks, MBO order IDs/flags, and MBP-10 levels (`feeds/databento.py:423–474`). MBP-10 is consumed by live possibility features (`possibility.py:1059–1095`) with a15-second freshness gate, and by the counterfactual execution-cost endpoint (`server.py:3281–3297`). MBO is exposed as bounded events and a temporary snapshot (`feeds/databento.py:1526–1625`); that does not itself establish a continuously reconstructed complete L3 book. Workspace depth explicitly returns `complete_book_snapshot=false` (`workspace_market_data.py:73–75`). Generic provider context has an explicit Brain/interrepo research-only projection, not automatic execution authority.

External blockers remain separate: current Finnhub receipt records credential present plus HTTP401 (`Engine automation_intelligence/provider_collection_v1/latest/finnhub.json:25–39`); UW screener likewise401; preferred Icarus Intrinio receipt records credential present plus401 (`Icarus automation_intelligence/provider_collection_v1/latest/intrinio.json:25–35`). No credential values were inspected. Current depth-primary corpus loss/budget/integrity and provider authentication/entitlement restrictions cannot be relabeled adapter success.

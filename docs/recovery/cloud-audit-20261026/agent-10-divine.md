# Agent 10 — Divine Providence interoperability audit

Read-only source review, 2026-10-26. Read root AGENTS and local canonical coordination/data-state files. No network, tests, runtime probing, source edits, or delegation. Findings describe checked-out code, not deployed behavior.

- **P1 — Windows failures do not reach the published Observatory assessment.** `.github/workflows/icarus-observatory.yml:37` runs a separate Windows full-system verification, but publication depends only on Ubuntu `collect` (`:105–106`) and passes only `needs.collect.result` (`:136`). `scripts/observatory/report.py:64–74` derives its receipt from that collection. A failed/timed-out Windows job can therefore coexist with a published passing atlas and incident reconciliation. Include Windows outcome/evidence in the receipt and publisher gate; a workflow-level red badge does not repair the published assessment.

- **P1 — Declared loopback client accepts arbitrary credential destinations.** `src/divine_providence/engine.py:17` accepts unrestricted `ICARUS_ENGINE_URL`; `:35–41` sends the engine bearer token to that origin for research requests through the default urllib opener. Unredirected headers protect a redirect hop, but do not validate the initial origin or disable ambient proxies. Reject non-loopback origins and use a proxy-free opener before treating this as a safe local-engine adapter. No token values were inspected.

- **P2 — Observatory output is engineering evidence, with no demonstrated live signal consumer.** Collector `scripts/observatory/collect.py:291–293` runs hub/validator suites; report `:74` explicitly sets `live_engine='not_observed'`. Publisher writes `observatory-history` (`scripts/observatory/publish.py:26`); Institution separately writes `research-history` (`scripts/institution/common.py:14`). A source search of Icarus `icarus_engine/*.py` found no references to either history branch or their receipt schemas. Icarus-engine's `config/federated_repo_evidence.json:33–43` lists producer source/workflow paths, not a receipt-ingestion adapter. Do not equate producer registration with runtime consumption.

- **Working interoperability is narrower and concrete.** Divine MCP exposes read-only engine GET wrappers (`mcp_server.py:162–202`), matching Icarus server routes. Icarus embeds four provenance-pinned NEXUS/AION modules (`icarus_engine/native_subsystems/source_manifest.json`) and consumes cached portfolio metadata through `subsystem_connections.py:96–137,169–188`; this is an actual native adapter, independent of Observatory history. AEGIS/JANUS/Infrastructure remain explicitly standalone (`connections.py:57–64`). Tour success deliberately excludes live-engine health (`tour.py:62–64`), so it cannot establish runtime readiness.

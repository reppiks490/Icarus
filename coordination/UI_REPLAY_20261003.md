## Proven defect and repair

An accepted background configuration job still held every target runner lock
through replay. Both actual `/status/public` and `/api/chart/TEST` requests
timed out in the new regressions. Health alone had concealed the dashboard stall.

Only public status/chart reads now have a bounded 50 ms lock attempt. While a
runner is busy they return detached pre-replay views, with `view_stale` and
`view_captured_at` metadata. Overview and asset headers label the snapshot.
Normal reads resume automatically after commit or rollback. Internal/default
status and chart consumers continue to wait for engine locks; these snapshots
cannot enter strategy or execution decisions.

Read views publish before metadata mutation and before a multi-asset batch.
Public portfolio accounting derives from the returned asset rows and preserves
the pre-batch equity epoch while any row is stale. This prevents fictitious net
profit from mixing old equity with staged capital or hiding old history behind
an uncommitted epoch. Fresh reads refresh only the requested cache, and copying
and chart slicing occur after releasing the runner lock.
